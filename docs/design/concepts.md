# 产品与核心概念

macops 希望解决的是「我机器上有哪些东西、该改哪一份、上次究竟改成了没有」。它提供一致的查找、预演和结果核对。Homebrew、mise、chezmoi、Skills CLI 和各 Agent 继续解释自己的配置及安装记录。把写入交给负责该格式的工具，可以沿用其现有行为和用户约定。

## 同名对象如何区分

| 对象 | 识别一份实例需要什么 | 谁负责实际内容 |
| --- | --- | --- |
| 软件 | 管理器、作用域、原生包身份。例如两个 npm prefix 可以各装同名包 | 原生包管理器持有包和维护状态 |
| Agent CLI 与配置 | CLI 有工具名、版本和执行文件。配置有客户端类型、启动名和实际配置目录 | Agent 保存模型、凭据、插件选项及项目设置 |
| 技能与插件 | 技能有来源、成员和部署位置。原生插件还需要市场、客户端和目标配置 | Skills CLI 或原生 Agent 维护安装 |
| 配置文件 | 管理源、目标根和目标文件。一个路径只有结合所属范围才有完整含义 | chezmoi 处理管理源格式、模板和应用行为 |
| 操作记录 | 原操作 ID、计划、作用域、阶段和后置证据 | macops 保存记录，原生工具和文件提供结果证据 |

列表优先显示读得懂的名称、渠道和位置。详情里的唯一 ID 适合消除歧义及绑定脚本。路径还可能被同名目录替换。涉及写入时，部分适配器绑定设备号和 inode 来识别实际目录，并在执行前复查。

## 从发现到可以维护

- **发现**表示读到了某些本机证据。覆盖不全意味着还有范围无法核对。
- **登记或接管**保存对象的身份或已观察基线。允许哪些写入取决于来源、配方和适配器支持的范围。比如 uv 可以记录基线，软件生命周期仍由用户通过 uv 维护。
- **启用**表示配置希望使用插件。确认安装还需要有效载荷和原生登记。**载入**是某次会话实际读取到能力，需要会话层证据。
- **漂移**表示已保存的预期与当前可读事实不同。**缺失**表示核验了不存在。**未知**表示证据不足。这三种情况会触发不同的下一步。
- **计划**描述拟执行的动作和目标。**操作记录**保存原计划及执行阶段。**回执**是用于后续维护和核对的持久证据，例如安装的来源、身份和达到的版本。

Claude Code 的两套配置可以共用一个可执行文件。为 `claude-mi` 装插件时，应该核对这一套配置的路径。另一个叫 `claude-glm` 的配置即使使用相同版本的 CLI，也仍有自己的插件登记和模型设置。两个客户端读取同一共享技能目录时，一次文件写入可以影响多个客户端。 [能力流程](../flows/capabilities.md)

## 什么时候执行，什么时候提示

来源、安装方式、作用域和适配器均满足条件时，macops 才能生成可执行候选。推荐模型仅解释公开证据。仅有文档支持的安装方式可以作为手动指引。用户确认的是具体目标和影响范围。计划生成以后，执行入口还要检查原目录和来源证据是否适用于当前状态。

原生调用退出只是一个观测点。只有适配器验证了对应后置状态，才能报告整次操作完成。外部状态无法核实时保留原记录，让后续核对有可靠依据。 [推荐与安装](../flows/recommend.md) · [恢复](../flows/recovery.md)
