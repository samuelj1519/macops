# 架构与设计

macops 是面向 macOS 的 Rust CLI。它统一对象、命令、目录查询和操作记录。软件与配置的原生管理器继续拥有各自的安装记录、受管配置、客户端缓存和服务状态。macops 的常规入口由单个二进制提供。Node、Brew、chezmoi 等外部程序仅在对应功能需要时参与运行。

## 模块与职责

| 模块 | 职责 |
| --- | --- |
| `cli`、`lib`、`context` | 解析命令、校验作用域与分派。普通命令共用上下文解析和迁移检查 |
| `output`、`browser`、`terminal` | 展示列表、详情、预览和原生命令进度。用户确认后由业务入口执行 |
| `recommend/` | 核对公开来源，分析并展示安装候选，独立管理模型配置和钥匙串 |
| `agent/` | 管理 Agent 工具、客户端配置和原生插件，负责配置选择、确认、恢复及目标发布 |
| `skills/`、`software/`、`config/` | 各自解释技能配方、软件实例和配置目标的原生契约、操作及核对结果 |
| `catalog/` | 汇总对象清单，解析选择器，读写版本索引和缓存 |
| `capability/`、`source/` | 管理能力归属和共享字段，核对固定来源与快照，按账本同步及发布 |
| `domain/`、`policy/` | 定义实例、计划、观察和回执。共享规则负责配置档案、资源目录和操作，以及路径和数据格式等共用校验 |
| `operations/`、`migration/` | 通用执行、受管命令环境、操作记录和恢复分派，以及独立的迁移核对与账本 |
| `platform/` | 处理子进程捕获、进程组时限、路径、目录句柄与文件身份 |

业务入口使用共享的执行和记录接口。`operations::recovery` 调用适配器核对既有操作，核对沿用原记录及已持有的锁。`operations::command` 从原作用域构造命令，`platform::process` 接收已构造的命令和审计回调。平台文件操作负责目录身份，业务层保存并解释自己的写入证据。

纯规则接收 I/O 层提供的文件身份、内容摘要、进程状态等证据，判断输入、计划和状态是否可接受。软件、配置、技能、能力和来源的专属规则在各自的 `rules/` 下。跨业务的配置档案、资源目录和操作规则分别位于 `policy/profile/`、`policy/catalog/` 和 `policy/operation/`。分散在业务目录的纯规则由 [覆盖率规则](../quality-policy.json) 的 `required_pure` 明确登记。

Provider 调用通过程序与独立参数构造。Catalog 中显式命令的可信度与本机脚本相同。

## 命令受理

`lib` 处理命令级别的校验和分派。内部 worker 根据原计划和启动许可执行。推荐设置只使用自己的配置上下文。迁移命令直接使用迁移事务的检查，允许在迁移待核对时进入恢复路径。其余命令共用迁移检查，再进入 JSON、纯文本或交互入口。在 `HOME` 缺失时，显式 `--home` 使用独立作用域，不继承环境中的管理器目录。

迁移标记可能在界面打开后出现。维护和核对动作各自在持锁时复查迁移状态和对应的原始证据。浏览器只负责交互和展示。 [命令受理状态图](models/README.md#命令受理与操作核对)

## 对象与所有权

软件实例用管理器、安装位置与原生身份区分。同名包可能出现在多个 npm prefix 或客户端档案。项目作用域、配置启用、已安装载荷和会话载入分别报告。发现为只读观察，采纳记录基线，实际写入权限取决于明确的来源契约。Unknown、缺失和漂移使用不同状态。

- Homebrew formula 绑定可执行文件、prefix、Cellar、配置证据及完整 formula 名。npm 绑定 prefix、包名、manifest 和适用的 npm 配置。mise 绑定实际安装目录与配置目录，写入前核对目录身份和 chezmoi 归属。各适配器调用原生命令并核验结果。 [uv 的维护范围](uv-readonly.md)
- Skills CLI 持有原生安装记录。macops 保存仓库、提交、成员、客户端、安装名和安装时变换。派生载荷只读取固定 Git 对象，按配方应用筛选、许可证、精确编辑及手动触发元数据。升级保留逻辑实例身份。原生客户端插件与独立技能使用不同配方。 [客户端插件](native-plugin-recipes.md)
- 独立 Codex 和 Claude Code 档案各自保留模型、认证和原生设置。macops 保存插件的启动偏好，并在启动时传递对应的原生参数。Cursor 项目插件声明单独展示，实际安装和会话加载由 Cursor 管理。
- 能力同步只修改配方拥有的字段。实时配置与静态 chezmoi 源分别记录原值，共享字段在最后一个归属释放后恢复。chezmoi 原生适配由原程序解释模板、忽略规则、源属性及状态，并沿用其 hooks、缓存与网络行为。
- AI CLI 的升级检查实际载荷、解释器、精确版本和已知来源约束。mise pin 与静态源声明收敛前再次核对原输入。支持的服务操作绑定用户域和已声明的服务身份。凭据检查只返回存在性，交互写入由凭据工具完成。

## 安装建议与管理清单

公开依据来自随程序发行的快照、调用者提供的本地资料和 GitHub 公开仓库。终端可从简短名称查找可能的仓库，核对选定仓库中同一提交的文档。匹配已登记配方或受支持的原生市场条目时，macops 提供安装预览。执行取决于来源证据、适配器范围、当前状态与用户确认。

`mo recommend --setup` 可选本地分析、DeepSeek 或自定义 OpenAI 兼容服务。推荐模型共用一条 `org.macops.recommend.api-key` 钥匙串凭据。凭据绑定到已确认的服务地址和配置目录。换钥时原位更新条目，以版本标记核对配置是否已发布。日常推荐静默读取凭据，系统要求授权时继续本地分析。启用远端辅助后，终端推荐可以发送公开仓库文档摘录和受支持工具是否存在的信息，请模型比较来源、交付类型与安装方式。模型结果仅用于建议展示。调用失败时可以继续使用本地分析。

设置向导只解析推荐配置所需的目录。保存和恢复用当前系统用户账户目录下的固定私有锁目录 `~/.config/macops/recommend-model.lock` 串行化，同一用户的自定义配置目录共用该锁。钥匙串修改与本地文件发布前均检查锁和配置的目录身份。软件维护的 `active.json` 由维护事务读取，推荐里的实际安装仍受维护恢复条件约束。

管理清单导出正式声明、原生能力登记、可验证的配置缓存和安装收据。输入通过型别、大小、摘要和作用域核验。预演分别显示本地证据差异和原生重放资格。重放的已验范围为已登记的同作用域单个 npm 项，要求正式配方与明确版本。已满足的项在锁内以真实观察核验；其他项委托原生安装或升级流程。

给 Codex 或 Claude Code 的已有配置安装插件时，推荐界面提供已核验的候选，`agent::plugin_install` 负责选择位置和确认，`agent::profile_install` 负责已有配置的核对、登记和逐个安装。客户端适配器检查原生结果，`agent::plugin_target` 核验写入内容并提交到选定配置。适配器通过安装阶段通知报告进度，终端统一显示。

## 操作与恢复

1. 解析唯一目标、权限和作用域，构建可读的计划。预演使用已有证据，遇到未解析目标则明确报告。
2. 确认后取得共享写锁，检查未完成操作，再验证计划、来源和目标身份。不同状态目录按 HOME 锁协调，同一状态根按目录身份和兼容写锁协调。
3. 持久化 `Prepared` 和原始输入。记录 `Running`、worker 和执行范围后才发启动许可。原生 supervisor 在需要时持有原 HOME 锁的引用。
4. 等待原进程及要求的作用域结束，检查结果及后置状态。只有成功证据齐备才提交收据与终态。原生操作可能部分完成，超时、错误或缺少原证据会保留阻断。
5. 恢复使用原操作 ID 与冻结的事实，先核对原 writer、原退出和后置证据。恢复沿用原范围与调用。外部状态不能证明时保留 `Unknown`，由对应渠道完成前向修复。

无参数的 `mo recover` 和终端历史从 `operations` 取得核对状态。可读取的活动记录覆盖历史中的同 ID 副本。活动记录损坏时，保留只读历史供诊断，暂停核对。已成功的原生阶段仍可能待登记，或需要确认是否继续下一个阶段。Claude 后续证据不完整时，列表仍可带 `incomplete` 返回候选，终端历史显示待查并暂停交互确认。确认时重查原记录及后续证据。Codex 或 Claude Code 仍需继续安装时，终端显示 `mo agent resume ID`。阶段收口使用退出码 3 表示整个安装仍需处理。

将配置文件纳入管理或停止管理时，先在私有目录验证原生单文件操作，再用已核对的目录身份发布管理源文件。实际配置文件保持原样。缓存、阶段文件与状态日志分别提供中断核验依据。

## 目录与可回收数据

macops 的配置、数据、状态和缓存分别解析 XDG 设置与显式目录参数。状态中的 active 记录、history、收据和迁移账本是持久依据。缓存索引按内容摘要保存，刷新时间、当前引用和清理所有权分别登记。内容相同可以复用，只有本程序确切创建并登记的对象能进入清理候选。

临时工作区按操作独占，在释放后清理。清理只处理身份、模式及摘要复验通过的自有文件。共享缓存、模型、客户端载荷及恢复材料按其所有者保留。
