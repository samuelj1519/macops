# 代码审查指南

先用公开命令描述这次改动改变了什么。例如「升级两个 Agent 时，一项已经满足目标，另一项仍须安装」。找到相应的业务流程和负责模块，再跟踪参数、计划、确认、外部调用、结果和回执。审查 Agent 生成的代码时也从这条链路开始。

## 先找到改动的影响范围

1. 固定要审查的提交或文件快照。读需求、差异和关联流程。列出受影响的 CLI、交互、脚本、配置及旧持久数据。
2. 找到真正做决定的业务函数和实际写入点。检查交互入口、直达命令和恢复入口是否仍使用相同的规则。
3. 为每条相关分支写下可观察结果。把「返回成功」拆成退出码、实际文件、原生命令调用次数、用户提示和回执。
4. 检查实现和测试是否覆盖这些结果。对锁、权限、恢复或旧数据等容易误判的分支，用合成夹具经过编译后的入口核对。
5. 审查结论写明文件和位置、触发条件、后果与验证方式。区分已证实的问题、证据缺口和可选的简化建议。核对过的证据应绑定同一份候选源码。

## 重点检查

| 改动 | 问题 | 需要的证据 |
| --- | --- | --- |
| CLI 参数或选择 | 同名对象是否明确。默认值、互斥参数、帮助与脚本入口是否一致 | 同名、空列表、取消、无终端、JSON 和实际帮助输出 |
| 安装或配置写入 | 计划与实际目标是否一致。确认后证据变动时是否停写。是否只改所拥有的字段 | 不同目标、目录被替换、源变化、无关配置保留和写入点对照 |
| 恢复或并发 | 谁持锁。子进程何时开始和停止。原状态不明时是否会误重试或错误收口 | 断点前后状态、第二个调用、进程组仍在、旧日志、重复执行次数 |
| 多目标或共享安装 | 是否按实际安装归并。哪些目标可以独立继续。未知结果是否阻止后续写入 | 同一安装两条记录、已达目标加待更新项、失败与未知混合 |
| 状态和终端输出 | 用户能否区分预演、取消、已完成、失败、仍需继续和结果未知 | 用 PTY 测终端交互与窄屏，用重定向和 `--json` 测脚本。核对退出码及未执行项 |
| 扩展和代码清晰度 | 模块是否拥有完整的业务步骤。规则是否在各调用方重复。错误与未知是否由显式类型表示 | 从两个入口追同一操作，核对依赖方向、可见性与绕过路径 |
| 性能 | 变慢来自网络、文件扫描、原生调用还是渲染。变快时是否仍执行同等核验 | 相同输入、冷暖缓存、耗时与调用数对照。规模增加时测最坏耗时和读取上限 |

代码宜在输入边界解析和校验，把读写结果交给类型清楚的规则，再由负责该业务的模块解释结果。检查抽象是否让调用方只传目标与意图，还是让调用方自行记住锁、检查顺序和内部状态。发现重复时，先找已有的完整流程，核对复用时能保留的行为。

## 演练审查一次批量升级改动

假设一段改动把 `skills::portfolio` 的循环改为「每条 Agent 记录调用一次原生升级」。先定位 [按 Agent 升级](../flows/capabilities.md#按-agent-升级) 的归并规则，再读 [`portfolio::perform`](../../crates/app/src/skills/portfolio.rs) 如何计算实际目标、回填结果并标记尚未执行项。

| 夹具 | 检查结果 |
| --- | --- |
| 两个 Agent 指向同一份实际安装 | 两行可都显示结果，原生命令只执行一次 |
| 两份独立安装，其中一份已经是目标版本 | 已达目标的安装不写入。另一份执行且核对后置状态 |
| 第一份原生操作有确定失败，第二份是独立安装 | 第一份保留失败。第二份可以按计划执行 |
| 第一份结果未知，第二份是独立安装 | 第二份显示「尚未开始」，没有执行调用。核对沿用第一份原记录 |

如改动逐行启动原生命令，第一组证据就能指出实际后果。编写审查意见时说明触发条件，例如「两个 Agent 使用同一共享目录时会触发两次原生调用」，并附上调用次数和出处。若改动还影响恢复，追到实际回执和测试。 [能力批量模型](../models/control_plane/AgentCapabilityBatch.tla) · [CLI 集成测试入口](../../crates/app/tests/cli.rs)

## 判断测试和模型证明了什么

纯规则测试适合核对输入判定。合成 CLI 测试适合核对真实参数、文件副作用和隔离的原生命令。PTY 测试适合核对选择、取消、光标和动态输出。TLA+ 模型适合查状态顺序、不变量和反例。真实客户端兼容性需要用相应版本的原生工具验证，运行范围应明确记录。

覆盖率用于定位没走到的路径。关键保障要有能发现错误实现的断言。改变公开契约或状态顺序时，同步更新对应文档和模型，保留对旧记录和已有入口的回归保护。 [开发与验证](verification.md) · [状态模型](../models/README.md)
