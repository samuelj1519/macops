# 技能和插件的安装与维护

能力指技能或插件。同一个 GitHub 仓库可以提供多个技能，也可以为不同 Agent 提供不同安装方式。客户端能从自己的目录读取技能，也可能读取同一个共享目录。先用 `mo skill --details` 看事实，再选择写入目标。 [能力命令](../commands/skills.md)

## 按 Agent 升级

```sh
mo skill upgrade owner/repo --agent claude-mi --agent claude-glm --dry-run
```

1. CLI 将命令交给 `lib::run_pipeline`，命中按 Agent 编排的请求时由 `skills::portfolio` 处理。它解析名称和来源，读取配置及现有安装。
2. `portfolio` 按目标生成计划，核对共享范围和固定来源。预演列出 Agent、位置、现有版本、目标版本和原因。
3. 确认后执行计划。相同物理目标与相同操作复用一次结果。原生插件交给客户端适配器，共享技能交给 Skills CLI 安装和核验流程。
4. 每项写完核对实际状态，将结果填回关联的 Agent。遇到未知结果时停止启动后续独立操作。

| 计划或执行遇到的情况 | 行为 | 下一步 |
| --- | --- | --- |
| 已达到目标 | 跳过该项的写入，继续其他目标 | 核对其他行 |
| 多行指向同一共享安装 | 只执行一次，各行复用结果 | 核对涉及的目录和读取方 |
| 共享目录尚未获得写入确认 | 脚本未提供 `--shared` 时阻止该项，交互入口在确认时说明共享影响 | 核对所有读取该目录的 Agent，包括未选择的 Agent |
| 插件目标目录与另一套 Agent 配置目录嵌套 | 暂停该项，避免跨配置写入 | 核对两套配置的实际目录 |
| 一项确定失败 | 记录失败，其余独立项可以继续 | 根据该行原因处理后重试 |
| 一项结果未知 | 记录待核对。关联项复用结果，未开始的独立项单独标出 | 先核对原结果，再重试未满足项 |
| 来源不明确或没有受支持的维护方式 | 暂停该项 | 明确来源，或按推荐中给出的原生途径维护 |

## 共享技能的安装与接管

共享技能的安装先解析固定 Git 来源和技能成员。用户确认范围后，由 Skills CLI 写入，macops 按原计划核对实际安装，再记录来源、成员、安装名和客户端等后续维护证据。一个仓库可以选择多个成员。仓库版本固定到标签或提交后，在命令中提供新的明确引用才会改变固定目标。

第一次维护其他方式装好的兼容技能时，程序可先提出接管当前安装。确认后以已核对的实际目录和版本记录基线。目录、来源或成员有歧义时，以结果提示为准。固定来源的派生交付走另一条受控路径，从固定 Git 对象构建，再按配方选择成员、应用许可约束、精确编辑及调用元数据。 [共享技能实现](../../crates/app/src/skills/native_skills_journey.rs) · [来源载荷实现](../../crates/app/src/source/source_payload.rs) · [共享技能模型](../models/control_plane/SharedSkillJourney.tla)

## 更新 Claude Code 插件市场并升级

如果市场仍固定在旧提交，或者当前使用本机目录，可先预演把一套配置更新到公开仓库的指定版本。

```sh
mo skill upgrade owner/repo@v1.2.0 --agent claude-mi --switch-source --dry-run
```

支持唯一用户级安装的单插件市场。旧来源可为已核验的本机目录，也可为同一 GitHub 仓库的已核验提交。上游须提供相同市场名和插件名。交互式升级会按配置展示旧来源、目标版本和将要执行的原命令，逐项选择确认或跳过。跳过的配置单独计数，其他已确认的升级继续。脚本更新来源须明确提供 `--switch-source`。

每套配置先更新来源声明并用 Claude Code 添加市场，核对后再更新插件。两个原生阶段独立记录。第一阶段已核验时可以继续第二阶段。原结果未知时先核对。最后核对版本、载荷及启停状态。 [换源实现](../../crates/app/src/agent/plugin_source_switch.rs) · [换源模型](../models/control_plane/SkillSourceSwitch.tla)

终端里的「原生命令」显示受支持适配器将执行的程序和参数，「原工具输出」显示该进程输出，「mo 升级结果」汇总各配置的结果。共享技能已符合目标时，结果会说明本次没有启动 Skills CLI。

## 启停、同步与卸载

启停更改受支持的插件配置。会话是否载入需要会话证据。卸载要求明确安装目标，受共享范围与原生维护条件限制。同步技能链接或档案配置时，只有声明中拥有的字段会被写入。同一个字段可能有多个依赖，解除最后一份归属时才恢复原值。

已有客户端的固定配方同源重装和公开仓库的首次安装分别核对不同条件。Cursor 项目声明可通过项目清单观察，账户市场和会话装载由 Cursor 处理。 [原生插件配方](../commands/native-plugin-recipes.md) · [目标发布](../../crates/app/src/agent/plugin_target.rs) · [同步实现](../../crates/app/src/capability/capability_sync.rs)
